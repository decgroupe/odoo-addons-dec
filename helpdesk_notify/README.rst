This module sends an internal notification email when a helpdesk ticket
is created automatically and no valid assignee is set for the target
team.

- Alerts the whole ticket team when a new ticket is created by automated
  flows (for example fetchmail or portal-driven creation).
- Skips the team broadcast when the ticket is already assigned to a user
  who belongs to that team.
- Includes a direct action link to open the created ticket from the
  email.

Technical details
-----------------

**Ticket creation hook**

The module extends ``helpdesk.ticket`` and overrides ``create()`` with
``@api.model_create_multi``. After record creation, it checks context
flags (``fetchmail_cron_running``, ``force_helpdesk_notify``,
``portal_ticket``) to decide whether the notification workflow must run.

**Recipient selection logic**

For each created ticket, ``_notify_new_ticket()`` receives the team and
assigned user from the original create values. If the assigned user is
missing or not in the team members, the module gathers team member
emails and sends one internal notification message to that distribution.

**Email rendering**

The message is sent through the mail template
``helpdesk_notify.created_ticket_internal_template``, with a custom QWeb
body (``helpdesk_notify.view_created_ticket_internal_template``) and a
record action URL generated by ``get_access_link()``.
